# Spike Findings

## Вопрос: есть ли легитимный способ читать публичные Instagram-аккаунты по критериям (не по своим/разрешённым), не строя anti-detection инфраструктуру?

**Ответ: да, но не через официальный API — через instagrapi под одним настоящим аккаунтом, в разумном темпе.**

### Факт 1 — официальный Instagram Graph API не подходит вообще
Business Discovery endpoint отдаёт данные только по аккаунтам, которые сами
дали разрешение через OAuth (свои Business/Creator-аккаунты). Произвольный
поиск по критериям/хэштегам для чужих аккаунтов **не предусмотрен
официальным API в принципе** — это не вопрос лимитов, а отсутствие
возможности. Значит официальный путь не годится под задачу «найти N
подходящих чужих аккаунтов».
[Instagram API Integration Guide 2026](https://www.getphyllo.com/post/instagram-api-integration-101-for-developers-of-the-creator-economy),
[Instagram Graph API 2026: Dev Questions](https://zernio.com/blog/instagram-graph-api)

### Факт 2 — instagrapi/aiograpi активно поддерживается, Python 3.10+
Неофициальная библиотека под приватный (мобильный) API Instagram,
активно живая в 2026, есть sync- (`instagrapi`) и async-версия
(`aiograpi`, тот же автор). Позволяет ровно то, что нужно: поиск по
критериям/хэштегам, чтение публичного профиля (bio, категория,
подписчики, контакты).
[instagrapi (GitHub)](https://github.com/subzeroid/instagrapi),
[aiograpi (GitHub)](https://github.com/subzeroid/aiograpi)

### Факт 3 — реальный риск честно назван в самой документации
«Private API automation is fragile in production: account trust, proxies,
device state, challenges and rate limits». Это подтверждает то, что мы уже
решили раньше в этом проекте: без фермы аккаунтов/прокси — риск временного
ограничения аккаунта при агрессивном использовании, это операционный риск,
а не вопрос обхода детекции спама (детекция спама — про массовую рассылку,
здесь автоматизации отправки нет вообще).

## Решение
- Библиотека: `aiograpi` (async, совместим с остальным стеком сервиса на
  asyncio/httpx, тот же паттерн, что уже в `telegram_sales_agent`).
- Один настоящий аккаунт компании, без прокси-ферм — тот же принцип, что и
  у Telethon-аккаунтов скаута.
- N жёстко ограничен < 50 на уровне контракта (не только UI) — держит
  темп в безопасной зоне и соответствует исходному ТЗ.
- Между запросами внутри одного задания — пауза (не мгновенный залп 50
  запросов подряд), конкретное значение — задача реализации, не спайк.

## Не решено этим спайком (сознательно, не блокирует план)
- Точный algoритм критериев поиска (по хэштегам? по геолокации? по
  подписчикам конкурентов?) — это описывается в самом диалоге с
  пользователем при настройке профиля поиска, не фиксируется здесь.
