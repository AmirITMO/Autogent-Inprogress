# Plan

Идём без пауз между стадиями (по явному указанию пользователя) — артефакты
пишутся, ворота фиксируются в `state.md`, но подтверждение на переход не
запрашивается.

## Шаг A — Email-канал: перенос паттерна скаута на B2B_EMAIL
**Готово когда:** дано B2B_EMAIL-канал с существующими `B2bEmailContact`/
лидами → когда открываешь `/channels/[id]` для него → тогда видно три
вкладки (Управление/Аналитика/Подробности), «Аналитика» показывает те же
7 метрик, что у скаута, с числами, совпадающими с ручным расчётом по
фикстуре; «Управление» открывает чат, отправка сообщения создаёт запись
в `AgentKbMessage` и (если LLM решит) обновляет `AgentKnowledgeBase.content`.

## Шаг B — Pull-эндпоинт базы знаний для b2b-email-agent
**Готово когда:** дан валидный `X-Api-Key` → когда `GET
/api/integrations/b2b-email-agent/knowledge-base?channelId=...` →
тогда 200 с `content`/`updatedAt`; без ключа — 401 (аналогично scout-agent,
проверяется тестом по образцу `scoutKnowledgeBaseApi.test.ts`).

## Шаг C — Instagram: очередь заданий на парсинг + сохранённые профили поиска
**Готово когда:** дан открытый канал INSTAGRAM → когда жмёшь «Спарсить N
аккаунтов», проходишь диалог из ~5 вопросов и он завершается → тогда в БД
появляется `InstagramSearchProfile` (сохранённые критерии) и
`InstagramScrapeJob` со статусом `PENDING`, `count = N` (N проверяется
< 50 на сервере, не только в UI).

## Шаг D — API для внешнего Instagram-сервиса (pull задач + push результатов)
**Готово когда:** дан `PENDING`-джоб → когда сервис делает `GET
/api/integrations/instagram-agent/jobs?status=pending` → тогда получает
джоб с критериями профиля; когда шлёт `POST .../contacts` с
`draftMessage` на аккаунт и затем `POST .../jobs/:id/complete` → тогда
джоб помечен `DONE`, счётчик найденного соответствует пришедшим контактам.

## Шаг E — Новый Instagram-сервис (отдельный, Python)
**Готово когда:** дан `PENDING`-джоб в тестовой БД → когда сервис
запускается с тестовым конфигом и опрашивает CRM → тогда за один цикл
опроса (без ожидания реального Instagram, спайк решает — реальный
скрейпер или контролируемый стаб на этой итерации) джоб переходит в
`DONE`, а в CRM появляются N `InstagramContact` с непустым `draftMessage`.
Реальный механизм скрейпинга — по итогам риск-спайка (Шаг C пайплайна,
не путать с Шагом C плана), не выбран заранее.

## Шаг F — Верстка Instagram-канала в CRM
**Готово когда:** дан INSTAGRAM-канал с готовыми `InstagramContact` →
когда открываешь «Подробности» → тогда видно таблицу с колонкой
«Черновик оффера» и сохранённые профили поиска с кнопкой «Искать по
этому профилю снова».

## Non-goals (явно вне скоупа)
- Автоматическая отправка сообщений в Instagram (уже решено раньше —
  только сбор базы, переписка вручную).
- Мульти-тенантность/раздельные OpenAI-ключи на канал — используем общий
  `OPENAI_API_KEY` CRM, как уже сделано для скаута.
- Реальный деплой нового Instagram-сервиса на прод-сервер в рамках этой
  сессии — контейнеризуем и документируем запуск, ручной деплой на VPS
  пользователь делает сам (тот же паттерн, что со скаутом).
