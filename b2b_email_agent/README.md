# b2b_email_agent

Отдельный сервис, ищущий целевые компании и составляющий черновики холодных
писем по заданиям из CRM (Autogent Platform, раздел «Каналы трафика» → B2B
email-рассылки). Не отправляет письма сам — только парсит сайты компаний и
генерирует черновик, отправку делает сотрудник вручную из CRM после
одобрения (вкладка «Спаршено»).

Архитектура и контракты — `docs/pipeline/` в корне основного репозитория.

## Как работает

Раз в `POLL_INTERVAL_SECONDS` (по умолчанию 30с) сервис спрашивает CRM про
задания в статусе `PENDING` (`GET /api/integrations/b2b-email-agent/
jobs?status=pending`, создаются кнопкой «Спарсить N компаний» в CRM). Для
каждого задания:

1. Читает текущую базу знаний канала (`GET .../knowledge-base`) — описание
   целевого клиента, продукта, тона, заполняется в CRM через чат «Управление».
2. Строит из неё 1-3 поисковых запроса одним вызовом OpenAI.
3. Ищет сайты компаний через Apify (`APIFY_SEARCH_ACTOR`, по умолчанию
   `apify/google-search-scraper`).
4. Читает содержимое каждого сайта через Apify (`APIFY_CRAWLER_ACTOR`, по
   умолчанию `apify/website-content-crawler`) — без своего браузера/прокси,
   вся нагрузка на стороне Apify.
5. LLM решает, подходит ли компания под критерии, и достаёт название/email.
6. Для подходящих — составляет черновик письма и пушит результат
   (`POST .../contacts`, статус `FOUND`) и закрывает задание
   (`POST .../jobs/:id/complete`).

## Переменные окружения (`.env`, рядом с этим файлом, не коммитить)

| Переменная | Назначение |
|---|---|
| `CRM_API_URL` | базовый адрес CRM, например `https://crm.autogentgroup.ru` |
| `B2B_EMAIL_AGENT_API_KEY` | тот же секрет, что в `.env.production` CRM |
| `OPENAI_API_KEY` | свой ключ, для поисковых запросов/извлечения/черновиков |
| `APIFY_TOKEN` | токен Apify — обязателен, весь поиск/парсинг сайтов на нём |
| `APIFY_SEARCH_ACTOR` | id актора для поиска компаний, по умолчанию `apify/google-search-scraper` |
| `APIFY_CRAWLER_ACTOR` | id актора для чтения сайтов, по умолчанию `apify/website-content-crawler` |
| `POLL_INTERVAL_SECONDS` | интервал опроса CRM, по умолчанию 30 |
| `MAX_DOMAINS_PER_JOB` | сколько сайтов максимум проверять за одно задание, по умолчанию 40 |

## Локальный запуск

```bash
pip install -r requirements.txt
# создать .env с переменными из таблицы выше
python main.py
```

## Docker

```bash
docker compose up -d --build
```

## Тесты

```bash
pip install -r requirements.txt
pytest
```

`scraper.py`/`crm_client.py` покрыты тестами с замоканными Apify/OpenAI/HTTP
(без сети). `offer_writer.py` не покрыт — требует реального вызова OpenAI,
тот же принцип, что в `instagram_scout_service`.

## Важное про отправку и спам

Этот сервис НЕ отправляет письма — только готовит черновики. Реальная
отправка (SMTP) настраивается в основном репозитории CRM (`SMTP_HOST`,
`SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM_EMAIL` в
`.env.production`) и срабатывает только по клику сотрудника «Одобрить и
отправить». Код не может решить репутацию отправителя за вас — это вопрос
DNS-записей домена отправителя (SPF/DKIM/DMARC) и постепенного прогрева
аккаунта/домена; без этого письма с высокой вероятностью попадут в спам
независимо от текста.
