# support_heartbeat_client

Дроп-ин модуль для проектов, которые уже сданы клиенту и переведены в CRM
Autogent Platform на этап **Поддержка** или **Постоплата**. Подключается к
разделу «Управление поддержкой» (`/support` в основной платформе) — платформа
показывает статус, время последнего пинга и открывает инцидент, если пинги
пропали или сервис сам сообщил об ошибке.

Платформа никогда не стучится в сервис клиента первой (у него обычно нет
публичного адреса, и это её не касается) — сервис сам репортит о себе,
тем же pull/push-принципом, что и остальные интеграции Autogent Platform
(`instagram_scout_service/crm_client.py` и соседи в основном репо).

## Установка

1. Скопируйте папку `support_heartbeat_client/` целиком в репозиторий
   клиентского проекта.
2. Добавьте зависимости из `requirements.txt` (или просто `httpx` +
   `python-dotenv`, если тесты не нужны в проде).
3. В карточке проекта на `/support/<id>` в платформе скопируйте heartbeat-URL
   и положите его в `.env` клиентского сервиса:

   ```
   SUPPORT_HEARTBEAT_URL=https://<платформа>/api/support/heartbeat/<токен>
   SUPPORT_HEARTBEAT_INTERVAL_SECONDS=60
   ```

   Токен в URL — это одновременно и секрет: он один на проект, и его
   компрометация раскрывает только возможность слать фейковые статусы по
   этому проекту (а не доступ к остальной платформе). При компрометации
   перевыпустите токен кнопкой на странице проекта.

## Подключение к основному циклу

```python
import asyncio
from support_heartbeat_client.heartbeat import HeartbeatConfig, heartbeat_loop

async def main():
    cfg = HeartbeatConfig()
    heartbeat_task = asyncio.create_task(heartbeat_loop(cfg))
    ...  # остальные таски сервиса
```

`heartbeat_loop` шлёт `status: "OK"` каждые `interval_seconds` — это
подтверждение "процесс жив", а не агрегатор ошибок. Если процесс упадёт
совсем, он просто перестанет слать пинги: это ловит отдельный сторож
`check-stale` на стороне платформы (помечает проект DOWN и открывает
инцидент, если пинга нет дольше 3 интервалов подряд).

## Репортить ошибки, а не только факт жизни

Если у сервиса есть точка, где он уже видит собственную деградацию
(например upstream API стабильно отвечает 5xx, или очередь не разгребается),
зовите `send_heartbeat` напрямую с реальным статусом — платформа откроет
инцидент сразу, не дожидаясь трёх пропущенных пингов:

```python
from support_heartbeat_client.heartbeat import send_heartbeat

try:
    await process_batch()
except Exception as e:
    await send_heartbeat(cfg, status="DEGRADED", detail=str(e))
    raise
```

Статусы: `OK`, `DEGRADED`, `DOWN`. Отправка heartbeat — best-effort: сетевая
ошибка или недоступность платформы только логируется и не роняет основной
цикл сервиса (`send_heartbeat` исключений не поднимает).
